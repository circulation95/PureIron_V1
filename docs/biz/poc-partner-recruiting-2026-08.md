## 0. 방식 변경 근거

기존 계획의 "시흥·안산 금속가공 현장 직접 방문 제안"은 D-20 안에서 성사 확률이 낮다. 콜드콜은 의사결정자 접촉까지만 평균 수 주가 걸리고, 거절 한 번에 일정 전체가 밀린다.

**인바운드로 뒤집는다.** 무상 제공을 공개하고 지원자를 받아 그중 조건이 맞는 1곳을 고른다. 아쉬운 쪽이 우리가 아니라 지원자가 되므로 협의 속도가 빨라지고, 여러 후보 중 **사례 공개에 동의하는 곳**을 고를 수 있다.

> 핵심: 이 활동의 목표는 매출이 아니라 **신청서 "적용사례" 칸에 쓸 수 있는 실제 현장 1곳 + 공개 동의**다. 이 두 가지가 없으면 아무리 잘 설치해도 공모전에는 못 쓴다.

## 2. 커뮤니티 목록 및 게시 주의사항

### ⚠️ 먼저 읽을 것 — 이 채널을 태우지 않는 법

거의 모든 실무 카페가 **상업적 홍보글을 금지**한다. 규정을 어기면 글 삭제로 끝나지 않고 **강퇴 + 재가입 차단**이라 채널이 영구히 닫힌다. 다음 3가지를 지킨다.

1. **가입 즉시 글쓰지 말 것.** 가입 후 공지·규정을 먼저 읽고, 며칠간 다른 글에 답글을 달아 계정 히스토리를 만든다. 히스토리 0인 계정의 첫 글이 모집글이면 스팸으로 처리된다.
2. **운영자에게 쪽지로 먼저 물을 것.** "무상 실증 파트너 모집 글을 올려도 되는지, 가능하다면 어느 게시판이 맞는지" — 허락받고 올리면 삭제 위험이 사라지고 오히려 운영자가 밀어주는 경우가 있다. **이 방법이 가장 안전하고 빠르다.**
3. **홍보문 형식을 쓰지 말 것.** 제품 자랑·가격·문의처 나열은 즉시 광고로 분류된다. §3의 글 형식을 따른다.

안녕하세요. 중소 제조현장용 경량 SCADA를 만들고 있는 개발자입니다.

현장에서 반복적으로 듣는 이야기가 있었습니다. 설비 알람은 뜨는데 **원인과 조치가 어디에도 남지 않아서**, 같은 문제가 석 달 뒤에 또 터지면 그때 처리했던 사람을 수소문해야 한다는 것이었습니다. 담당자가 바뀌면 그마저도 끊깁니다.

이 문제 하나만 보고 만들었습니다. 코드는 GitHub에 공개했습니다.

**하는 일**

- OPC-UA / Modbus TCP / Siemens S7 / LS Electric / Mitsubishi MELSEC / AB ControlLogix에서 태그를 **읽어** 웹·모바일 대시보드로 표시
- 알람이 뜨면 AI 에이전트가 실시간 태그·이력·설비 상태를 직접 조회해서 원인 후보와 확인 순서를 설명
- 조치 내용을 기록하면 이력으로 쌓여서, 같은 알람이 재발할 때 과거 조치를 바로 참조

**하지 않는 일** (이게 더 중요합니다)

- **쓰기·제어를 하지 않습니다.** 코드에 전역 read-only 플래그가 있어서 드라이버 write, REST 태그 write, 에이전트의 제어 도구가 전부 차단됩니다. 관례가 아니라 코드로 막혀 있고 테스트로 고정돼 있습니다.
- 기존 PLC 로직을 건드리지 않습니다. 제어는 그대로 PLC가 합니다.
- **고장을 예측한다고 하지 않습니다.** 예측 모델은 없습니다. 이력을 남기고 설명하는 데까지입니다.
- 승인한 태그만 읽습니다. 나머지는 기본 차단(default-deny)입니다.

**찾고 있는 것**

실제 현장 한 곳에서 2주간 돌려보고 싶습니다. 시뮬레이터에서는 다 되는데, 진짜 현장의 태그 이름과 알람 패턴에서 이게 쓸모가 있는지는 해봐야 압니다.

- **비용: 없습니다.** 설치와 2주 운영, 철수까지 무상입니다. 유지보수 계약을 전제로 하지 않습니다.
- 제가 직접 방문해서 설치하고, 끝나면 깨끗하게 걷어냅니다.
- 조건: 수도권 서남부(시흥·안산·화성·인천 등), 이더넷 연결 가능한 PLC, PC 1대와 유선랜.
- 한 가지 부탁: **결과를 사례로 공개하는 데 동의**해 주셔야 합니다. 회사명은 익명 처리 가능하고, 공개 범위는 사전에 함께 정합니다.

## 4. 지원자 스크리닝 기준

지원이 여러 건 오면 아래 순서로 거른다. **잘못된 현장 하나를 고르면 일주일을 통째로 날린다.**

### 필수 (하나라도 안 되면 제외)

| # | 조건 | 확인 질문 |
|---|---|---|
| 1 | **사례 공개 동의** | "익명 처리 조건으로 공모전 신청서에 사례를 기재해도 될까요?" — **NO면 즉시 제외.** 이게 전부다 |
| 2 | 당일 왕복 가능 거리 | "공장 위치가 어디신가요?" — 시흥·안산·화성·인천·부천 우선 |
| 3 | 지원 프로토콜 PLC | "PLC 제조사와 모델이 어떻게 되나요? 이더넷 포트가 있나요?" — LS·미쓰비시·지멘스·AB·Modbus TCP·OPC-UA |
| 4 | 의사결정자 참여 | "사장님이나 공장장님이 직접 확인해 주실 수 있나요?" — 실무자만 있으면 중간에 엎어진다 |
| 5 | 8/11~8/12 설치 일정 수용 | "다음 주 초에 반나절 정도 시간이 되실까요?" |

### 가점

- **금속가공·프레스·사출** 업종 (공모전 테마 ⑧ 금속가공과 일치)
- 알람이 실제로 자주 뜨는 라인이 있음 (조용한 라인은 2주간 보여줄 게 없다)
- 이미 스마트공장 지원사업 경험 있음 (정부사업 언어가 통한다)
- 담당자가 카페·오픈채팅에서 기술적인 질문을 해온 경우 (설치 협조도가 높다)

### 감점 / 주의

- "무료면 일단 받아보죠" — 설치 협조가 안 나온다
- 제어·자동화까지 기대하는 곳 — v1 범위 밖이라 반드시 실망시킨다. **첫 통화에서 명확히 자른다**
- 예측정비 성능을 기대하는 곳 — 예측 모델이 없다. 같은 이유로 자른다

- **스마트제조혁신협회의 매칭이 공모전 참가 기업에게 상시 제공되는지 미확인.** 2025년 사례는 전시회 연계 행사였다. 8/3 통화로 확인.
- **각 카페의 홍보글 규정 원문 미확인.** §2 주의사항은 일반적 카페 운영 관행 기준이며, 가입 후 공지에서 직접 확인해야 한다.
- **카페 활성도 미확인.** 검색 결과에 최근 글이 잡히는 곳 위주로 골랐으나, 실제 일일 방문자·반응 속도는 가입 후 판단.
- **GitHub 리포지토리 현재 상태.** 비공개로 추정(외부 접근 불가)이나, 조직 설정·접근 권한 문제일 수 있다.
- **커뮤니티 모집의 응답률.** 근거 데이터 없음. 0건일 가능성을 전제로 8/8 체크포인트와 아웃바운드 백업을 뒀다.
