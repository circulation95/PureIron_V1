# PureIron — 기존 PLC 제어를 바꾸지 않고 read-only로 붙는 현장 모니터링·트러블슈팅 도구

> 설비보전팀장·전기팀장·자동화 담당자용 1페이지 기술 설명 자료입니다. 고객/영업용이며 SOT(정본)가 아닙니다. 정본 결정은 [docs/wiki/gtm/first-contract.md](../wiki/gtm/first-contract.md)·[docs/wiki/sot/architecture.md](../wiki/sot/architecture.md), 상세 제안서는 [read-only PoC 제안서](read-only-poc-proposal.md)를 따릅니다.

**PLC 제어 로직은 그대로 두고, 승인한 주요 태그만 read-only로 읽어** 알람 원인 후보와 조치 절차·이력을 남기는 **현장용 모니터링·트러블슈팅 도구**입니다. "기존 제어를 건드리지 않고 안전하게 붙을 수 있는가"를 3주 이내 현장 PoC로 확인합니다.

---

## 1. 연결 방식 요약 — PLC는 그대로, 승인 태그만 read-only

- 제어는 지금처럼 **PLC가 그대로** 담당합니다. PureIron은 PLC 프로그램·로직·파라미터를 **변경하지 않습니다.**
- 설비보전팀장·전기팀장이 **승인한 주요 태그만** 읽기 전용으로 수집합니다. write/control 명령은 이번 PoC에 포함하지 않습니다.
- 수집한 데이터로 대시보드·알람·조치 이력·AI 트러블슈팅 계층만 위에 얹습니다. 설비 동작 경로에는 개입하지 않습니다.

## 2. PoC 구성도 (read-only 단방향 데이터 흐름)

```
[PLC / 설비]  ──(승인 태그 read-only)──▶  [PureIron 수집]  ──▶  ┌─ 대시보드(웹/모바일)
  제어 로직 그대로                          가능하면 수집망         ├─ 알람 발생 → 확인 → 조치
  (변경/write 없음)                         분리·접근 제한          ├─ AI 조치 설명(Agent troubleshooting)
                                                                  └─ 조치 이력 저장(온프레미스 우선)
```

- 데이터는 **PLC → PureIron 방향으로만** 흐릅니다(읽기). 반대 방향 제어 명령은 없습니다.
- 기본 데이터는 **현장(온프레미스)에 남깁니다.** 외부 접근·원격지원은 고객이 동의한 범위에서만 제한적으로 엽니다.

## 3. 안전 원칙

- **제어 로직 미변경.** PLC 프로그램·인터록·시퀀스를 수정하지 않습니다.
- **write/control 없음.** 사람 승인 없는 쓰기·제어는 물론, 무인 자동 제어도 이번 PoC 범위가 아닙니다.
- **승인된 태그만 수집.** 수집 대상은 담당자와 사전 합의한 목록으로 한정합니다.
- **AI는 사람 판단 보조.** 알람 원인 후보·조치 시나리오를 설명할 뿐, 자동으로 설비를 제어하지 않습니다.
- **네트워크는 분리·접근 제한 우선.** 가능하면 수집 환경을 기존 제어망과 분리하거나 접근 범위를 제한합니다(현장 조건별 확정).

> "설비에 영향이 전혀 없다"를 과장해 보장하지 않습니다. **제어 로직을 변경하지 않고 read-only로만 수집하며, 현장 조건에서 불간섭을 함께 검증**합니다.

## 4. 지원 프로토콜과 확인 필요 정보

지원 프로토콜: **OPC-UA / Modbus TCP / Siemens S7 / LS Electric / Allen-Bradley ControlLogix / Mitsubishi MELSEC.**

> 위 프로토콜을 v1에서 지원하지만, "모든 PLC·모든 프로토콜 지원"을 약속하지는 않습니다. 현장 기종·펌웨어·통신 조건에 따라 실제 연결 가능 여부를 점검 단계에서 확인합니다.

확인이 필요한 정보:

- PLC 기종·모델, 통신 프로토콜, 여유 통신 포트/슬롯.
- 읽고자 하는 주요 태그·주소 후보(알람/상태 중심).
- 수집 장비를 둘 위치와 네트워크 접근 조건(분리/접근 제한 가능 여부).
- 데이터 저장·외부 접근 허용 범위에 대한 내부 정책.

## 5. 3주 PoC 절차

| 단계 | 기간 | 내용 |
|---|---|---|
| 1주차 — 사전 점검 | 1주 | PLC 기종·프로토콜 확인, 네트워크 접근 가능성 확인, 수집 태그 후보 선정(설비보전·전기·SI 협의), 성공 기준 합의 |
| 2~3주차 — read-only 현장 PoC | 2주 | 승인 태그만 읽기 전용 연결, 대시보드 구성, 알람→확인→조치 이력 흐름 검증, AI 조치 설명 검증, 불간섭 확인 |

총 3주 이내가 기본이며, 범위가 커지면 일정을 재협의하거나 정식 구축/별도 계약으로 분리합니다. 실제 PLC 연결이 부담되면 demo/simulator로 흐름을 먼저 확인한 뒤 실제 연결로 넘어갑니다.

## 6. 고객 준비물 체크리스트

- [ ] PLC 기종·프로토콜 정보와 담당자(설비보전팀장/전기팀장/SI) 연결
- [ ] 수집 대상 주요 태그 후보 목록(현장에서 함께 확정)
- [ ] 수집 장비 설치 위치와 네트워크 접근 조건(분리/접근 제한 가능 여부)
- [ ] 데이터 저장·외부 접근 허용 범위에 대한 내부 동의
- [ ] PoC 성공 여부를 함께 판단할 담당자

## 7. 이번 PoC에서 하지 않는 것

- PLC 제어 로직 수정, 무인 자동 제어, 사람 승인 없는 write/control.
- MES/ERP 전체 대체, 고객별 대형 SI 커스터마이징.
- 모든 PLC/프로토콜 지원 약속, 24/7 SLA 보장.
- 예측정비 정확도 보장, 수율·공정 개선 수치 보장.

> 중앙 관제나 승인 기반 제어는 장기 방향일 수 있으나, 이번 PoC/첫 계약에서는 약속하지 않습니다. 제어가 필요한 단계는 별도 안전 검토와 별도 계약으로 다룹니다.

## 8. 포함 기능

태그 수집(트렌드/이력 포함), 대시보드(웹/모바일), 알람(발생→확인→조치), 조치 이력, AI 트러블슈팅(Agent) — 알람 원인 후보와 조치 시나리오 설명(사람 판단 보조), 로그인/권한/감사(Auth/RBAC/Audit) 최소 구성.

## 9. 다음 액션

2. **네트워크 점검** — 수집 장비 위치, 수집망 분리/접근 제한 가능 여부를 확인합니다.
3. 위 확인 후 승인 태그만 read-only로 연결하는 2주 현장 PoC에 착수합니다.
