# PureIron 설비 모니터링 PoC 제안서 (표준 read-only)

> 이 문서는 고객/영업용 **제안서 초안**이며 SOT(정본)가 아니다. 첫 계약·PoC·가격에 관한 정본 결정은 [docs/wiki/gtm/first-contract.md](../wiki/gtm/first-contract.md)를 따른다. 실제 고객 제출 시에는 아래 가격 anchor를 현장 조건으로 산정하고, `[   ]` 빈칸을 채워서 사용한다.

---

## 1. 요약

PureIron은 **기존 PLC 제어를 전혀 건드리지 않고**, 설비 상태와 알람을 읽어 대시보드로 보여주고, 알람이 나면 AI가 원인 후보와 조치 방법을 설명하며, 그 조치 이력까지 남기는 **경량 설비 모니터링 시스템**입니다.

이 제안서는 금속·가공·프레스·사출 등 일반 중소 제조 현장을 위한 **표준 read-only(읽기 전용) PoC**를 안내합니다. 총 3주 이내(1주 사전 점검 + 2주 현장 PoC)로, 기존 설비와 생산을 그대로 둔 채 작은 범위에서 효과를 먼저 확인하실 수 있습니다.

- **무엇을 하나:** 승인된 주요 설비 태그를 읽기 전용으로 수집 → 대시보드 → 알람 → AI 조치 설명·이력.
- **무엇을 안 하나:** 설비를 제어하거나 PLC 로직을 바꾸지 않습니다. 쓰기/제어 명령은 이 PoC에 포함하지 않습니다.
- **왜 지금:** "같은 설비 문제가 반복되는데 원인·조치·이력이 안 남는다"는 문제를, 기존 설비를 위험에 빠뜨리지 않고 작게 검증할 수 있습니다.

---

## 2. 고객 문제

현장에서 이런 어려움을 자주 겪습니다.

- **설비 이상·알람이 나도 원인, 조치, 이력이 체계적으로 남지 않아 같은 문제가 반복됩니다.** (가장 큰 문제)
- 설비 상태를 알려면 현장에 직접 가거나 전화로 물어봐야 합니다.
- 담당자가 바뀌거나 자리를 비우면, 예전에 어떻게 조치했는지 알기 어렵습니다.
- 기존 설비를 함부로 건드렸다가 생산이 불안정해질까 봐, 새로운 시스템 도입이 부담스럽습니다.

PureIron은 이 중에서도 **"반복되는 설비 문제의 원인·조치·이력을 남긴다"**는 문제 해결에 집중합니다. 예쁜 대시보드가 목적이 아니라, 문제 재발을 줄이는 기록과 설명이 목적입니다.

---

## 3. PureIron 제안

> **기존 PLC 제어를 건드리지 않고, 설비 상태와 알람을 AI가 설명해 조치 이력까지 남기는 경량 모니터링 시스템.**

- **현장 밖에서도 공장이 보입니다.** 웹/모바일에서 주요 설비 상태와 알람을 확인합니다.
- **알람이 나면 AI가 설명합니다.** 알람 원인 후보와 조치 시나리오를 사람이 이해할 수 있게 알려줍니다. (자동 제어가 아니라 사람 판단을 돕는 보조입니다.)
- **조치 이력이 자동으로 쌓입니다.** 누가 언제 어떤 알람을 어떻게 처리했는지 남아, 다음에 같은 문제가 나면 참고할 수 있습니다.
- **기존 설비를 유지한 채 시작합니다.** 제어는 그대로 PLC가 담당하고, PureIron은 데이터를 **읽어서** 관제·알람·이력 계층만 얹습니다.

---

## 4. PoC 목표

이번 PoC의 목표는 "완성된 시스템 납품"이 아니라 **"기존 설비를 건드리지 않고도 설비 상태·알람·조치 이력이 실제로 도움이 되는지"를 작은 범위에서 확인**하는 것입니다.

- 승인된 주요 태그를 읽기 전용으로 안전하게 수집할 수 있는지 확인합니다.
- 현장 밖에서 설비 상태를 파악할 수 있는지 확인합니다.
- 알람 → 확인 → 조치 이력 흐름이 실제 현장에서 돌아가는지 확인합니다.
- AI 조치 설명이 현장 담당자에게 쓸모 있는지 확인합니다.
- PoC 기간 동안 설비 제어·생산 안정성에 아무 영향이 없음을 확인합니다.

---

## 5. PoC 범위: 포함 / 제외

### 포함 (실제 현장 read-only PoC)

- 기존 PLC/설비에서 **승인된 주요 태그를 읽기 전용으로 수집** (트렌드/이력 저장 포함).
- 실시간 상태 **대시보드** (웹/모바일).
- **알람** 발생 → 확인 → 조치 이력.
- **AI 조치 설명(Agent troubleshooting)** — 알람 원인 후보·조치 시나리오 설명(사람 판단 보조).
- 로그인/권한/감사(Auth/RBAC/Audit) 최소 구성.

### 영업/미팅용 데모와의 구분

Simulator + 3D 트윈 + AI Agent + Work Order를 함께 보여드리는 **풀 데모**는, 대표·공장장님께 흐름을 이해시켜 드리기 위한 **미팅용 데모 패키지**입니다. 이는 실제 현장 read-only PoC 기본 범위와는 구분되며, 현장 PoC에는 위 "포함" 항목만 들어갑니다.

### 제외 (이번 PoC에서 약속하지 않는 것)

- PLC 제어 로직 수정.
- 무인 자동 제어.
- 사람 승인 없는 쓰기/제어(write/control).
- MES/ERP 전체 대체.
- 고객별 대형 SI 커스터마이징.
- 범용 no-code SCADA 빌더.
- 모든 PLC/프로토콜 지원 약속.
- 24/7 SLA 보장.
- 예측정비 정확도 보장.
- 공정 최적화/수율 개선 수치 보장.

> 중앙 관제나 승인 기반 제어는 PureIron의 장기 방향일 수는 있으나, **이번 PoC/첫 계약에서는 약속하지 않습니다.** 제어가 필요한 단계는 별도의 안전 검토와 별도 계약으로 다룹니다.

---

## 6. 진행 일정: 1주 점검 + 2주 PoC (총 3주 이내)

### 1단계 — 사전 데모 / 현장 점검 (1주)

- 미팅용 데모(Simulator/3D 트윈/AI Agent/Work Order)로 흐름 공유.
- 고객 페인 확인 및 PoC 성공 기준 합의.
- 현장 PLC/프로토콜 확인.
- 네트워크 접근 가능성 확인.
- 수집할 주요 태그 후보 선정(SI/전기팀장 협의).

### 2단계 — read-only 현장 PoC (2주)

- 승인된 주요 태그만 읽기 전용으로 연결.
- 웹/모바일 대시보드 구성.
- 알람 발생 → 확인 → 조치 이력 흐름 검증.
- AI 조치 설명(Agent troubleshooting) 검증.
- 결과 리뷰 및 정식 구축 전환 판단.

> 총 기간은 기본 3주 이내입니다. 범위가 이보다 커지면 일정을 재협의하거나, 정식 구축/별도 계약으로 분리합니다.

## 7. 기술 / 보안 / 설비 안정성 원칙

- **기존 PLC 제어를 건드리지 않습니다.** PureIron은 제어 로직을 변경하지 않으며, 설비 데이터를 **읽어서** 관제·알람·이력 계층만 제공합니다.
- **쓰기/제어 명령은 이번 PoC 범위에 포함하지 않습니다.**
- **승인된 태그만 읽습니다.** 수집 대상 태그는 SI/전기팀장과 사전에 합의한 주요 태그로 한정합니다.
- **수집망 분리/접근 제한을 우선합니다.** 가능하면 PureIron 수집 환경을 기존 제어망과 분리하거나 접근 범위를 제한합니다. (현장 구성별로 확정)
- **데이터는 온프레미스(현장) 우선.** 기본 데이터는 고객 현장에 남깁니다. 리포트·대시보드·원격지원·외부 접근은 **고객이 동의한 범위에서만** 제한적으로 엽니다.
- **불안하시면 데모부터.** 실제 PLC 연결이 부담되면, demo/simulator로 흐름을 먼저 확인한 뒤 실제 연결로 넘어갑니다.

- PoC 결과 리뷰 자료(확인된 효과, 확장 후보 라인/설비, 정식 구축 시 고려사항).

## 9. 성공 기준

아래 후보 중 고객과 합의한 항목을 이번 PoC의 성공 기준으로 채택합니다. 구체 수치·기간은 미팅에서 함께 정합니다.

1. 기존 PLC 제어를 건드리지 않고 주요 태그 수집에 성공한다.
2. 웹/모바일에서 주요 설비 상태를 확인할 수 있다.
3. 알람 발생 → 확인 → 조치 이력 흐름이 검증된다.
4. AI가 알람 원인 후보와 조치 시나리오를 설명한다.
5. PoC 기간 동안 설비 제어/생산 안정성에 영향이 없다(불간섭 검증).
6. 대표/공장장/설비보전 담당자가 "현장 밖에서도 상태 파악이 된다"고 인정한다.
7. 정식 구축 시 확장할 라인/설비 후보가 나온다.

> PureIron은 예측정비 정확도, 수율/공정 개선 수치 같은 성과를 보장하지 않습니다. 성공 기준은 "기능 개수"가 아니라 "현장에서 실제로 쓸모 있었는가"입니다.

## 10. 가격 anchor 및 레퍼런스 할인 조건

아래 금액은 **협상 출발점(anchor)**입니다. **실제 견적은 현장 범위, 태그 수, 라인 수, 네트워크 조건, 지원 범위에 따라 조정**됩니다.

| 단계 | 가격 anchor |
|---|---|
| 사전 데모 / 현장 점검 | 무료 또는 실비 |
| 2주 read-only 현장 PoC | 300만 ~ 700만 원 |
| 첫 1~2건 레퍼런스 할인 PoC | 100만 ~ 300만 원 |
| 정식 구축비 | 1,000만 ~ 3,000만 원 / 라인 또는 소규모 현장 단위 |
| 유지보수 / 구독 | 월 50만 ~ 200만 원 또는 연 600만 ~ 2,400만 원 |

- **레퍼런스 할인:** 첫 1~2개 현장에 한해, 사례 공유(레퍼런스) 협조를 조건으로 전략적 할인이 가능합니다.
- 사전 데모/현장 점검은 영업 진입 비용으로 무료 또는 실비로 진행할 수 있으나, **현장 PoC 자체는 소액 유료가 원칙**입니다.

## 11. PoC 이후 정식 구축 전환

PoC가 성공하고 아래 신호가 확인되면 정식 구축으로 전환합니다.

**전환 신호(예):**
- 추가 라인/설비 연결을 요청한다.
- 알람/리포트/이력 기능을 계속 쓰고 싶다고 한다.
- 대표/공장장/설비보전팀이 함께 리뷰 미팅을 잡는다.
- 기존 수기/전화/엑셀 보고를 PureIron으로 대체하고 싶다고 한다.
- 정식 구축 견적서를 요청한다.

**전환 방식:**
- 전환 신호 + 성공 기준 충족 + 합의된 가격/계약 조건 수락 시 정식 구축으로 넘어갑니다.
- 전환 시 확장 범위(추가 라인/디바이스)와 운영 책임 범위를 명시합니다.
- 제어가 필요한 단계는 **별도 계약 + 별도 안전 검토** 대상으로 분리합니다.

## 12. 고객이 준비할 것

원활한 PoC를 위해 아래를 준비해 주시면 좋습니다.

- 대상 라인/설비 1개(또는 소규모 설비군) 지정.
- PLC 기종/프로토콜 정보 및 담당자(설비보전팀장/전기팀장/SI) 연결.
- 수집 대상 주요 태그 후보 목록(현장에서 함께 확정).
- PureIron 수집 장비를 둘 위치와 네트워크 접근 가능 여부.
- 데이터 저장/외부 접근 허용 범위에 대한 내부 동의.
- PoC 성공 여부를 함께 판단할 담당자(대표/공장장/설비보전).
